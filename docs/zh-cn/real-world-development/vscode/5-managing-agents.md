使用智能体模式时，GitHub Copilot 会自主探索代码库、提出更改、编辑文件并运行命令。由于 Copilot 会在本地实时工作，VS Code 中的 Copilot Chat 会持续显示每次工具调用和文件编辑。可以在行内查看每个差异、接受或拒绝单项更改，也可以通过后续提示引导对话，在不离开编辑器的情况下完善或扩展工作。

本练习将学习如何：

- 实时监控无障碍智能体的工作。
- 审查并接受建议的文件编辑。
- 在会话进行期间引导智能体，要求它添加浅色模式切换开关和高对比度模式切换开关。

## 场景

你在[练习 4][previous-lesson]中使用的无障碍自定义智能体正在实现高对比度模式。工作进行期间，设计团队又提出了一项需求：为觉得默认主题太暗的用户添加浅色模式切换开关。不必从头开始新对话，可以引导现有会话扩展工作范围。

## 监控 Copilot 的进度

Copilot Chat 视图会显示智能体的每个步骤，包括探索的文件、运行的命令和提出的编辑。每次文件编辑都会在聊天中以差异形式显示，并提供 **Keep** 和 **Undo** 控件。

1. 返回练习 4 中使用的 Copilot Chat 视图。
2. 智能体工作时，滚动聊天内容并查看每次工具调用。你会看到文件读取、文件编辑以及需要运行的终端命令。
3. 智能体提出文件编辑时，差异会显示在行内：
   - 选择 **Keep** 接受更改。
   - 选择 **Undo** 还原更改，让智能体重新尝试。
4. 也可以打开聊天顶部的 **Files changed** 指示器，查看智能体在本次会话中修改的全部文件。

> [!NOTE]
> 如果工具调用需要权限（例如运行终端命令），智能体会暂停并显示 **Allow** 提示。只批准你认可的命令。

5. 等待智能体完成高对比度模式。完成后应会显示总结所做更改的消息。

## 引导智能体添加浅色模式

高对比度模式已经就绪。接下来扩展同一对话，添加浅色模式切换开关。由于仍在同一个聊天会话中，智能体会保留之前工作的上下文，包括修改的组件、使用的样式方案和本地存储模式。

1. 在 Copilot Chat 输入框中发送以下后续提示：

    ```plaintext
    做得不错！现在请在高对比度切换开关旁边添加浅色模式切换开关。浅色模式应采用相同的模式：通过 local storage 保留设置，并且能从 UI 的同一区域访问。用户应能分别启用高对比度模式和浅色模式。
    ```

2. 智能体会继续工作，探索已进行的更改并提出浅色模式的实现。
3. 像审查高对比度模式一样，逐项审查新更改。对每个差异选择 **Keep** 或 **Undo**。
4. 如果智能体的实现方向不符合预期（例如尝试以不喜欢的方式重构切换 UI），可以选择聊天输入框旁的 **Stop** 按钮停止任务，然后发送澄清提示。

> [!TIP]
> 引导正在进行的会话比从头开始更快。可以用后续提示要求调整（“简化 CSS，改用 CSS 变量，不要重复选择器”）、纠正方向（“不要添加第三个开关，请将浅色模式集成到现有设置面板”）或扩展范围（“为两个切换开关都添加键盘快捷方式”）。

## 审查工作集

提交工作前，快速检查智能体修改的所有内容。

1. 在 VS Code 中打开 **Source Control** 视图。
2. 审查更改文件的完整列表。应能看到 Astro 组件、样式和相关测试的更新。
3. 打开几个更改的文件并查看差异。确认自定义智能体所要求的无障碍模式已体现在代码中，例如 ARIA 属性、键盘导航、语义化 HTML 和 local storage 持久化。
4. 确认满意后，在 Source Control 面板中暂存并提交更改。下一课会发布这些更改。

## 总结与后续步骤

你使用 Copilot Chat 智能体模式监控并引导了一个正在进行的会话：逐项审查文件编辑、接受或拒绝更改，并发送后续提示扩展工作，同时保留上下文。

本课介绍了以下内容：

- 实时监控智能体的工作。
- 接受或拒绝单个文件编辑。
- 在会话进行期间使用后续提示引导智能体。

在[下一课][next-lesson]中，你将通过拉取请求发布无障碍功能，并审查本实验中本地自定义智能体生成的更改。
